# Guide — Trace a Live Metric Through the Architecture

Activity: **Observe only.** Opening Architecture, filtering, selecting a
documented path, and following a tool/reference link do not change the world.

## Trace a Selected Metric from Engine to Export

1. Start from the panel or action whose value you are investigating. Confirm
   the world, exact subject or metric ID, sample tick, age, and evidence label.
2. Open contextual help and choose **Trace data path**. The Architecture route
   retains the current world, stable selections, world-tick range, and an
   appropriate metric path where one is registered.
3. Read **Live context** before interpreting highlights. A selected path is
   documentary focus; only a separately marked recent request is Observed.
4. Follow the path from the Engine/Domain owner through Transport, Browser
   transformation, Surface, and optional External export.
5. At every step compare field, unit, transformation, cadence, and evidence.
   Stop if a unit changes without a stated conversion or if sample ticks are
   incompatible.
6. Select a node to inspect its stable ID, endpoint, maintained source path,
   route, help, and reference. Source metadata is not a browser file link.
7. Select a relationship to read its evidence type and whether its mapped
   endpoint was observed in the current 30-second browser window.
8. Switch to **Text view** and confirm the same nodes and relationships without
   relying on spatial position or colour.
9. Open the target tool or reference and use Back to return to the same
   architecture selection and investigation context.
10. If the engine disconnects, retain the static path but treat old live
    highlights and values as stale.

Expected result: you can state where the value is owned, how it is transported,
which browser transformations are mechanical, where it is displayed or
exported, and which parts were actually observed. You should not claim that a
static edge or selected path proves runtime execution.
